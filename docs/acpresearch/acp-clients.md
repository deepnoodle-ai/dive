# ACP clients and control planes

_Source review: 2026-09-26 (America/New_York). Repository links below are pinned to the commits inspected. This is a source and documentation review, not an interoperability test._

## Main finding

ACP gives a client a session-oriented conversation protocol, live `session/update` notifications, client-side permission decisions, and optional agent-owned session discovery and reattachment. The clients examined add materially different state around that protocol. Zed converts notifications into editor thread state and gives the agent access to editor files and terminals. `acpx` owns local processes, serializes turns, journals events, and exposes a separate resumable watch cursor. OpenHands Canvas places the ACP process behind its own agent server and conversation API. Those client layers, rather than ACP alone, supply the durable control-plane behavior relevant to Nvoken and Mobius. [Zed update handler](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/acp_thread/src/acp_thread.rs#L3028-L3141), [acpx session model](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/sessions.md#L7-L18), [Canvas architecture](https://github.com/OpenHands/OpenHands/blob/47a10808d78561546a02555d0d2c7fa96fa96300/docs/ACP_AGENTS.md#L8-L31).

## Zed: what an editor client expects

- Zed launches an agent command and connects over line-delimited stdio JSON-RPC. It advertises client file read/write, terminal, terminal authentication, form/URL elicitation, and session config options; compaction and notice support are gated by a Zed beta flag in this snapshot. An ACP agent that relies on client file or terminal operations will encounter real implementations in Zed, but must check advertised capabilities rather than assume every client offers them. [Connection setup](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/agent_servers/src/acp.rs#L680-L725), [capabilities](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/agent_servers/src/acp.rs#L632-L670), [file/terminal handlers](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/agent_servers/src/acp.rs#L5253-L5315).
- Zed turns `agent_message_chunk`, `agent_thought_chunk`, tool-call starts/updates, plans, usage, titles, commands, mode/config changes, compaction, and notices into thread UI state. Tool-call content has separate paths for content blocks, diffs, and terminals. A Dive adapter should emit stable tool-call IDs and incremental status/content rather than only final text if the goal is useful Zed UI. This is an inference from Zed's handlers, not a protocol conformance requirement. [Update dispatch](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/acp_thread/src/acp_thread.rs#L3028-L3141), [tool content](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/acp_thread/src/acp_thread.rs#L2175-L2205).
- Permission requests are interactive agent-to-client RPCs tied to a session and tool call. Zed shows an authorization state for that call and returns the selected outcome; cancellation clears the pending authorization. This is a client decision point, not something the agent can infer from a tool-call notification. [Permission handler](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/agent_servers/src/acp.rs#L5083-L5129).
- Zed supports agent-advertised `session/list` with cwd/cursor pagination, and `session/load` or `session/resume` only when the agent advertises the corresponding capability. `load` and `resume` are separate code paths; a Dive adapter should implement them deliberately if editor reopen matters. [Listing](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/agent_servers/src/acp.rs#L431-L475), [load and resume](https://github.com/zed-industries/zed/blob/bda9c0bd43a8d235d82adb01ea5bc875b861ecfc/crates/agent_servers/src/acp.rs#L1659-L1755).

## acpx: the headless client and its added control plane

`acpx` is a headless ACP client with saved records scoped by `(agent command, absolute cwd, optional name)`. A live queue owner holds one agent connection for that record and serializes follow-up prompts through local IPC; the CLI can also make one-shot runs. It distinguishes agent-side `session/list` from its own local records. Its shared runtime lets an application and CLI attach to one **same-user, same-host** owner, but the project explicitly says this is not a network service or an isolation boundary for untrusted clients. [Sessions](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/sessions.md#L7-L54), [queue behavior](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/prompting.md#L87-L106), [shared runtime](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/shared-sessions.md#L1-L53), [trust boundary](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/shared-sessions.md#L102-L106).

The key distinction is **ACP session identity versus replayable event identity**. `acpx` writes an additional local journal with `message`, `turn_started`, and `turn_result` events, each with an opaque cursor; `requestId` belongs to an acpx submission and differs from a JSON-RPC request ID. `sessions watch --cursor` replays retained events and follows live ones without starting or cancelling the agent. Its watch cursor is expressly different from ACP `session/list` pagination. Rotation can expire a cursor, and an owner dying before a settled result returns `WATCH_OUTCOME_UNKNOWN`; acpx does not pretend such a prompt safely completed or automatically replay it. This is the closest precedent here for Nvoken's cursor-based streaming, but it is an **acpx extension layered on ACP**, not an ACP `session/update` guarantee. [Watch contract](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/session-watch.md#L22-L82), [journal event types and cursor](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/src/session/journal.ts#L24-L30), [unknown-outcome handling](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/src/session/watch.ts#L96-L105).

For crash recovery, the normal CLI path respawns an agent, tries advertised `session/resume` **or** `session/load`, and documents a fallback to a **new** ACP session if reconnect fails. That fallback preserves a local record but can change the underlying conversation identity. By contrast, the shared runtime and portable imports require the saved provider session to resume and fail rather than silently start a new conversation. A remote orchestrator should make this distinction explicit in its contract. [CLI recovery](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/sessions.md#L233-L243), [strict shared resume](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/shared-sessions.md#L46-L53), [import behavior](https://github.com/openclaw/acpx/blob/c62ae8cd86757e2dba644ed7b402d6a36d75031e/docs/sessions.md#L125-L138).

## Registry: discovery is not a capability contract

The ACP Registry is a curated **agent distribution index**. Entries describe identity, release, license, icon, and how to launch a binary, `npx`, or `uvx` package. The inspected schema has no static fields for `session/load`, `session/resume`, tool updates, file/terminal access, or permission behavior. The registry's CI checks valid `authMethods` in the initialize handshake; it does not make registry presence proof of all session capabilities. Clients still need the live ACP initialize response and runtime validation. At the inspected commit, 42 `agent.json` manifests were present; that count is a repository snapshot, not a compatibility count. [Registry README](https://github.com/agentclientprotocol/registry/blob/e67a956e238f9ef4139e0cf9f22cb176aef4cb0c/README.md#L3-L38), [schema](https://github.com/agentclientprotocol/registry/blob/e67a956e238f9ef4139e0cf9f22cb176aef4cb0c/agent.schema.json#L1-L78), [format](https://github.com/agentclientprotocol/registry/blob/e67a956e238f9ef4139e0cf9f22cb176aef4cb0c/FORMAT.md#L1-L48).

## OpenHands Canvas: ACP behind a separate backend

Canvas itself talks to an OpenHands agent server; that backend spawns the ACP CLI over stdio and owns credentials, tools, and persistent conversation state. The SDK's `ACPAgent` maps one OpenHands `step()` to one completed ACP assistant turn, relays chunks and tool-call progress into OpenHands events, and stores the ACP session ID plus cwd in conversation state. On a later start it calls `session/load`; an ACP protocol error can fall back to a new session, while transport failures propagate. Thus Canvas demonstrates a remote browser/control surface **over OpenHands' backend API**, not remote ACP transport alone. [Canvas ACP guide](https://github.com/OpenHands/OpenHands/blob/47a10808d78561546a02555d0d2c7fa96fa96300/docs/ACP_AGENTS.md#L8-L31), [SDK mapping](https://github.com/OpenHands/software-agent-sdk/blob/d77ada7a030b3acaa82593d402632680361dfe42/openhands-sdk/openhands/sdk/agent/acp_agent.py#L1-L16), [live bridge](https://github.com/OpenHands/software-agent-sdk/blob/d77ada7a030b3acaa82593d402632680361dfe42/openhands-sdk/openhands/sdk/agent/acp_agent.py#L1243-L1308), [saved identity](https://github.com/OpenHands/software-agent-sdk/blob/d77ada7a030b3acaa82593d402632680361dfe42/openhands-sdk/openhands/sdk/agent/acp_agent.py#L2368-L2383), [load fallback](https://github.com/OpenHands/software-agent-sdk/blob/d77ada7a030b3acaa82593d402632680361dfe42/openhands-sdk/openhands/sdk/agent/acp_agent.py#L3189-L3256).

An optional third-party contrast is ACP UI: its browser/mobile clients use WebSocket and a stdio-to-WebSocket bridge, while browser mode advertises no host filesystem access. Its documented persistent bridge keeps the agent alive through a dropped mobile connection, then reattaches with `session/load`. This shows that remote transport is possible with additional bridge and host-lifecycle machinery; it does not supply a portable durable event cursor by itself. [ACP UI README](https://github.com/formulahendry/acp-ui/blob/cd9c3cb464a4b321bff652101953a64c07473e31/README.md#L11-L15), [remote capability/bridge behavior](https://github.com/formulahendry/acp-ui/blob/cd9c3cb464a4b321bff652101953a64c07473e31/README.md#L170-L199), [reattachment](https://github.com/formulahendry/acp-ui/blob/cd9c3cb464a4b321bff652101953a64c07473e31/README.md#L258-L265).

## Implications to test for Dive, Nvoken, and Mobius

1. **For Dive as an ACP agent:** ship a useful stream of message chunks, tool-call start/progress with stable IDs, diff and terminal content when available, and truthful session capability declarations. Test against Zed's displayed thread and permission prompt, not merely a JSON-RPC handshake. This is an implementation recommendation inferred from Zed's client behavior.
2. **For a service that drives ACP agents:** decide whether resumption must preserve the same agent conversation. If yes, require `load`/`resume` and fail clearly on loss; do not adopt acpx's ordinary CLI fallback-to-new semantics invisibly. Preserve a distinct local conversation ID, ACP session ID, and turn/request ID.
3. **For durable remote viewing:** put a service-owned event log, cursor, retention policy, turn settlement, and unknown-outcome state around ACP. `session/load` replays conversation history from the agent, but is not equivalent to replaying every previously observed live update with a stable cursor. acpx's watch layer is a concrete local example; Canvas uses a separate backend boundary.
4. **For discovery:** use the registry to install and launch candidate agents. Probe initialize capabilities, authentication, session lifecycle, file/terminal methods, and permission behavior before claiming compatibility.

_Limits: No ACP clients or agents were executed. The OpenHands and ACP UI sections are targeted checks of ACP-facing behavior, not full product reviews. Repository activity, release versions, and registry membership can change after this snapshot._
