## Highlights

Anthropic cost estimates now price 1-hour prompt-cache writes correctly.
With the extended-cache feature on, Dive writes stable breakpoints with a
1-hour lifetime, which Anthropic bills at 2x input. Before this release Dive
priced those writes at the 5-minute rate of 1.25x, so `Usage.Cost` came in
low. `llm.Usage` now reports the 1-hour subset of cache writes, and `CostOf`
prices it separately. The long-context tier is included, for example Claude
Haiku 5.5 above 100k tokens.

History cache anchors now stay on the same blocks from turn to turn. They are
placed at fixed positions from the start of the conversation instead of
counting back from the moving tail. A 1-hour entry written on one turn can
then be read after an idle gap instead of being rewritten at a new offset.
This changes where breakpoints land on every Anthropic request, extended
cache or not. Only the positions change, not the number of breakpoints.

No code changes are needed. If you read cache-write counts from `Usage`,
`CacheCreationInputTokens` is still the total, and the new 5-minute and
1-hour fields are subsets of it.

## Changelog

### Added

- **Anthropic 1-hour prompt-cache write usage and pricing.** `llm.Usage` parses
  5-minute and 1-hour cache-creation token counts, and `llm.PricingInfo` prices
  1-hour cache writes at 2x input (including long-context tiers).

### Changed

- **Anthropic prompt-cache history anchors stay at fixed block positions across
  turns.** `placeCacheAnchors` anchors fixed multiples of `cacheAnchorGap`
  before the tail instead of shifting with the tail on every call.
